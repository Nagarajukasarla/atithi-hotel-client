# New hotel-operations project — Bun, Vite, Tailwind CSS, and shadcn/ui setup plan

> File name intentionally follows the requested spelling: `NEWDESIGN.IMPLEMENATATION.md`.

## Goal

Create a **new**, clean Vite + React + TypeScript project using **Bun**, **Tailwind CSS**, and **shadcn/ui**. It replaces the current Ant Design-based `vendor` implementation over time, but does not modify, delete, or copy over the existing project yet.

At the end of this setup only, running the app must show a completely blank white screen. Do not build the header, sidebar, routes, dashboard, rooms, bookings, forms, tables, or any product UI in this phase. The folder structure and foundation should nevertheless support all of those features and a future backend.

## Copy/paste implementation prompt

> Set up a brand-new hotel-operations frontend using Bun, Vite, React, TypeScript, Tailwind CSS v4, and shadcn/ui. The current project at `vendor` is the functional/design reference only; do not edit it and do not carry over Ant Design, `@ant-design/icons`, MobX, or its per-component CSS files. This setup phase must create only the application foundation, configuration, folders, an API boundary, and a blank white starter screen. Do not implement any business page or UI component.
>
> Create the project as a sibling to the existing repository, for example `D:\resource\Projects\Hotel Management\atithi-client`. Never scaffold over `D:\resource\Projects\vendor`.
>
> Use Bun for every command—never `npm`, `npx`, `pnpm`, or `yarn`. Begin from `D:\resource\Projects\Hotel Management`:
>
> ```powershell
> bun create vite atithi-client --template react-ts
> cd atithi-client
> bun install
> bun add react-router-dom @tanstack/react-query
> bun add -d tailwindcss @tailwindcss/vite @types/node
> bunx --bun shadcn@latest init -t vite
> ```
>
> During the shadcn initializer, select the Vite project, TypeScript, the `src` directory, the `@/*` import alias, CSS variables enabled, and the project’s preferred neutral base/style. Let the shadcn CLI add its own required packages and generated files (`components.json`, `src/lib/utils.ts`, theme CSS, and its utility dependencies) rather than hand-copying them. Do **not** add a catalog of shadcn components in this setup phase; add components only when a page actually requires them. If the installed CLI does not accept `-t vite` for an existing project, run the same command interactively as `bunx --bun shadcn@latest init` and select Vite.
>
> Configure Vite with React SWC, the Tailwind Vite plugin, and the `@` alias. Remove the old bundle visualizer, Ant Design optimize-dependency entries, custom manual chunks, fixed port requirement, and Ant Design assumptions from the legacy Vite config. The intended shape is:
>
> ```ts
> // vite.config.ts
> import path from "node:path";
> import react from "@vitejs/plugin-react-swc";
> import tailwindcss from "@tailwindcss/vite";
> import { defineConfig } from "vite";
>
> export default defineConfig({
>     plugins: [react(), tailwindcss()],
>     resolve: {
>         alias: { "@": path.resolve(__dirname, "./src") },
>     },
> });
> ```
>
> Configure the same `@/*` → `./src/*` alias in both `tsconfig.json` and `tsconfig.app.json`, because the Vite alias alone does not give TypeScript/editor resolution. Keep strict TypeScript enabled.
>
> Use Tailwind v4 through the Vite plugin. `src/index.css` must start with `@import "tailwindcss";`, then contain only safe global foundations: `box-sizing: border-box`, `html/body/#root { min-height: 100%; }`, `body { margin: 0; background: #fff; }`, inherited button/input font rules, and any CSS variables generated by shadcn/ui. Do not recreate the legacy `assets/styles/*.css` directory. Page and feature styling must later live in Tailwind class compositions or narrowly scoped CSS only when utilities cannot express it.
>
> Replace Vite’s demo assets, counter state, logo, and default styles. Keep `src/main.tsx` minimal: load `index.css`, wrap the app in `React.StrictMode`, `BrowserRouter`, and `QueryClientProvider`, then render `App`. Create a single shared `QueryClient` with conservative defaults (for example, retry once and refetch on window focus disabled) in `src/lib/query-client.ts`; it is infrastructure only and must make no request. Do not use MobX in the new project. Server data will use TanStack Query, while temporary page-only state will use React state/reducer.
>
> Make `App.tsx` deliberately blank for this phase:
>
> ```tsx
> export default function App() {
>     return <main className="min-h-svh bg-white" aria-label="Hotel Operations" />;
> }
> ```
>
> Do not add visible text, Vite branding, buttons, cards, a navigation shell, loading spinners, page routes, placeholder dashboards, or mock data. The acceptance criterion is a white browser viewport with no console errors.
>
> Add the directory structure below. Empty folders should contain a `.gitkeep` where Git would otherwise omit them. Create no implementation files in feature/page folders during this foundation phase except for the listed infrastructure files. Keep current product terminology and boundaries from `vendor`: overview, bookings, rooms, payments, settings, layouts, booking/room data, and route/auth boundaries.
>
> ```text
> atithi-client/
> ├─ public/
> ├─ src/
> │  ├─ app/
> │  │  ├─ providers/                 # AppProviders later centralizes router/query/theme providers

> Establish a backend-ready boundary without making a backend request yet:
>
> - Add `.env.example` with `VITE_API_BASE_URL=http://localhost:3000/api` and no secrets.
> - Add `src/app/config/env.ts` to validate/read `import.meta.env.VITE_API_BASE_URL` and export a single config object.
> - Add `src/services/api/http-client.ts` as the sole future fetch wrapper, responsible for base URL, JSON headers, `AbortSignal`, normalized errors, and future authentication-token injection. It must not be called from `App`.
> - Endpoint modules belong in `src/services/api/` (for example, `rooms.api.ts`, `bookings.api.ts`); TanStack Query hooks belong next to their domain in `src/features/`. UI components never call `fetch` directly.
> - Keep API transport types distinct from UI/domain view models. Use mapper functions at the service/feature boundary when an API response does not match the screen’s needs.
> - Do not put API URLs, credentials, mock data, or business calculations directly in components.
>
> Preserve the architecture of the legacy project without copying its technology decisions:
>
> | Existing `vendor` area                                       | New-project home                                                   | Setup-phase action                                                                            |

> | `pages/Overview`, `Booking`, `Rooms`, `Payments`, `Settings` | `src/pages/`                                                       | Create folder only; add route/page implementations later.                                     |
> | `components/layouts/`                                        | `src/components/layout/`                                           | Create folder only; sidebar/header/AppLayout later.                                           |
> | `components/feature/`                                        | `src/components/feature/{overview,bookings,rooms}/`                | Create domain folders only. Keep pages as composition layers.                                 |
> | `components/core/`                                           | `src/components/common/` and `src/components/ui/`                  | Add shadcn primitives later through its CLI; project-specific shared elements go in `common`. |
> | `data/`, `stores/`, `theme/`                                 | `src/features/`, `src/services/api/`, `src/lib/`, `src/constants/` | Replace ad-hoc global mock stores with typed query hooks and API services.                    |
> | `types/*.d.ts`                                               | `src/types/*.ts`                                                   | Use exportable modules, not global declaration files.                                         |
> | `utils/`                                                     | `src/lib/` or `src/hooks/`                                         | Add only utilities proven to be shared.                                                       |
> | Ant Design + icons                                           | shadcn/ui + Tailwind + `lucide-react`                              | Never install Ant Design in the new project.                                                  |
>

## Dependency policy

Install now only what is needed for the platform foundation:

| Package                                                                                | Reason                                                                                  |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `react`, `react-dom`, `typescript`, `vite`, `@vitejs/plugin-react-swc`                 | Vite React + TypeScript application foundation (provided by the Vite template).         |
| `tailwindcss`, `@tailwindcss/vite`                                                     | Tailwind v4 integrated through Vite.                                                    |
| `shadcn` and shadcn CLI-managed dependencies                                           | Component registry/configuration and future generated components.                       |
| `class-variance-authority`, `clsx`, `tailwind-merge`, `tw-animate-css`, `lucide-react` | Installed by shadcn when required; avoid manually duplicating incompatible versions.    |
| `react-router-dom`                                                                     | Route boundaries ready for the Overview, Bookings, Rooms, Payments, and Settings pages. |
| `@tanstack/react-query`                                                                | Future server-state caching, request lifecycle, and invalidation.                       |
| `@types/node`                                                                          | Required by the `node:path` Vite alias configuration.                                   |

Do **not** install now: `antd`, `@ant-design/icons`, MobX, Recharts, date-picker libraries, table libraries, form libraries, or any page-specific shadcn components. Add each only when a documented page requirement justifies it. This keeps the white-screen foundation small and avoids locking in unnecessary dependencies.

## Completion checklist

- A new sibling Vite project exists; the legacy `vendor` project is unchanged.
- `bun.lock` is created/updated in the new project and all commands used Bun.
- Tailwind is loaded via `@tailwindcss/vite` and `@import "tailwindcss"`.
- shadcn/ui is initialized with `components.json`, the `@` alias, and generated utility support.
- The required domain/layout/API folders exist, but no product pages or UI are implemented.
- `.env.example` and a single API client boundary exist; no request is made during startup.
- `bun run typecheck`, `bun run lint`, and `bun run build` succeed.
- `bun run dev` renders a basic blank white screen with no errors.
